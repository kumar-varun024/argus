#### Summary & Description

During security analysis of `api.service.io`, a Ssrf vulnerability was identified at endpoint `/fetch_url`. The vulnerable input vector is the `url` parameter. The vulnerability was triggered using payload: `http://169.254.169.254/latest/meta-data/`.

#### Steps to Reproduce

1. Navigate to the target endpoint `/fetch_url` on host `api.service.io`.
2. Inject the security verification payload into the parameter `url`: `http://169.254.169.254/latest/meta-data/`.
3. Submit the request and inspect the server response for indications of ssrf.

#### Proof of Concept Payload

```http
http://169.254.169.254/latest/meta-data/
```

#### Impact Analysis

An attacker could coerce the application server to make unauthorized requests to internal network services, cloud metadata endpoints, or adjacent private infrastructure.

#### Recommended Remediation

Implement strict allowlisting of permissible destination hosts and protocols. Block requests to private IP ranges (RFC 1918) and cloud metadata services (e.g., 169.254.169.254).

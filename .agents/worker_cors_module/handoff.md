  - `CORSMutationGenerator` / `CORSPayloadGenerator`: Implements 5 evasion strategies (`ORIGIN_CASING`, `PROTOCOL_SMUGGLING`, `SUBDOMAIN_INJECTION`, `HEADER_DUPLICATION`, `PREFLIGHT_ENUMERATION`).
  - `CORSAnalyzer`: Analyzes response headers (`Access-Control-Allow-Origin`, `Access-Control-Allow-Credentials`, `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`, `Vary`) across 6 detection modes:
    1. Origin reflection (`ACAO: <arbitrary-origin>`, `ACAC: true`)
    2. Null origin acceptance (`Origin: null` -> `ACAO: null`, `ACAC: true`)
    3. Wildcard with credentials (`ACAO: *` and `ACAC: true`)
    4. Subdomain trust abuse (`Origin: https://attacker.target.com` -> `ACAO: ...`)
    5. Pre-flight bypass & permissive OPTIONS responses
    6. Origin parser differential (`target.com.attacker.com`, `attacker-target.com`, regex unescaped dot, protocol downgrade)
    - Rejects false positives (same-origin reflection, unauthenticated wildcard on public endpoints).
  - `HTTPHeaderAuditor` / `HeaderAuditor`: Implements 8 HTTP security header compliance audits:
    1. Content-Security-Policy (missing CSP, unsafe-inline, unsafe-eval, wildcard sources `*` / `http:` / `data:`, missing frame-ancestors)
    2. Strict-Transport-Security (evaluated on HTTPS: missing, max-age < 31536000, missing includeSubDomains, missing preload)
    3. X-Frame-Options (missing when CSP frame-ancestors absent, misconfigured values)
    4. X-Content-Type-Options (missing nosniff)
    5. Referrer-Policy (missing, unsafe-url, no-referrer-when-downgrade)
    6. Permissions-Policy (missing, unconstrained wildcards `*` on camera/microphone/geolocation)
    7. X-XSS-Protection (explicitly 0 or missing without CSP)
    8. Cache-Control on sensitive endpoints (missing no-store on sensitive/auth routes; suppressed on static assets)

## 2. Logic Chain
1. **Target Dissection & Probing**: The collector aggregates candidate endpoints from mission state (`endpoints`, `live_hosts`, `target`, `evidence`). For each endpoint, `CORSProber` dispatches multi-vector requests generated by `CORSMutationGenerator`.
2. **Analysis & False Positive Filtering**: `CORSAnalyzer` checks the response headers against RFC specifications and security best practices. If arbitrary origins are reflected or wildcards are paired with credentials, high/critical findings are produced. Safe cases (such as same-origin reflection or public endpoints returning wildcard without credentials) are discarded.
3. **Security Header Compliance**: `HTTPHeaderAuditor` evaluates 8 browser protection policies. Conditional dependencies (e.g. suppressing missing XFO when CSP `frame-ancestors` is active, suppressing HSTS on plain HTTP, suppressing Cache-Control on static `.css`/`.js`) ensure accurate, zero-noise findings.
4. **Quadruple State Publishing**: When valid findings are detected, the collector records evidence in `mission.evidence`, appends vulnerability models to `mission.vulnerabilities`, links nodes and edges in `mission.attack_surface_graph`, and notifies `mission.publish_finding()`.
5. **Platform Integration**: Tool registry, planning task generator, plugin adapters, attack surface builder, and CVSS calculators seamlessly resolve `cors_headers` tasks and findings throughout the scan lifecycle.

## 3. Caveats
- `CORSProber` defaults to `timeout=10.0s` per request; in production environments with hundreds of thousands of endpoints, concurrent async probing or rate limiting should be tuned according to target network conditions.
